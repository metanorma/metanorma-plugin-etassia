= metanorma-plugin-etassia

Metanorma AsciiDoc extension that renders diagram blocks through https://github.com/etassia/etassia[Etassia], the pure-Ruby diagram interpreter — no Java, no external renderer, no server.

== Purpose

Replaces the metanorma-plugin-plantuml pipeline (PlantUML JAR / server) with Etassia: the same `[plantuml]`-style authoring experience, rendered in-process by an owned engine.

== Status

The `etassia` block, the `[plantuml]` drop-in block and the `plantuml_image::` macro are registered. Test corpus: mn-samples-pdfa `sources/bpg-tagged-pdf-syntax` (real `[plantuml]`/`@startsalt` documents).

== Usage

[source,adoc]
----
[etassia]
....
<diagram source>
....
----

Etassia was formerly named Sirena. The `[sirena]` block name still works and
renders exactly as `[etassia]` does, so existing documents keep compiling.

== `plantuml_image::` macro

The block macro `plantuml_image::file.puml[]` (registered by metanorma-standoc
for the PlantUML JAR) is also taken over. The file is read relative to the
document, `!include` also resolves beside it, and the diagram is rendered by
Etassia to an SVG under `_plantuml_images/`, with the same attributes as the
`[plantuml]` block (`id`, `title`, `width`, `alt`, ...). A failure warns and
falls back to a listing. Only SVG is produced; `png`, `pdf`, `txt` and `eps`
are reported as unsupported.

The output file is named after the diagram (`@startuml name` or
`@startuml(id=name)`), sanitised to stay inside the images directory; two
diagrams with one name get `name.svg` and `name_2.svg`.

== Activating in `metanorma compile`

Metanorma does not discover this plugin on its own. Without it, `[plantuml]`
blocks are rendered by the stock PlantUML plugin (Java). Load it explicitly:

[source,sh]
----
bundle exec metanorma compile -r metanorma-plugin-etassia -t <flavour> doc.adoc
----
